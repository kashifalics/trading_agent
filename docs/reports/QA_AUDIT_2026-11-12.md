# QA audit of the live platform (2026-11-12)

Scope: the deployed site (https://trading-agent-frontend-sigma.vercel.app) and API, all 15 pages at desktop (1440 px) and phone
(390 px) width, plus a code and dependency review. Methods:
- **Page sweep:** a Playwright sweep that timed every page and API call and checked for errors, wrong text ("NaN", "undefined",
  "null") and sideways scrolling.
- **Accessibility:** axe-core on every page.
- **Server checks:** authentication, CORS, security headers and rate limiting tested from outside.
- **Dependencies:** `npm audit` and `pip-audit`.
- **Usability:** a manual review of each page's screenshot.

Severity: **High** = wrong or stale information shown as current, or the site unusable under normal load. **Medium** = visible
defect or wasted resources. **Low** = polish or accepted risk.

## Findings and what was done

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | High | **The API was overloaded.** A trivial request (`/health`) took 1-8 s and Gold Research 5-24 s. Causes: the 840 KB Gold Research summary was sent uncompressed and re-parsed on every request; every open Signals tab re-analysed its instrument twice a minute, on top of the background cycle that already does it; SQLite ran without a write-ahead log, so reads queued behind the paper cycle's writes. | Fixed: gzip compression; `GET /signals/{symbol}` and a sync that fetched nothing reuse the latest analysis (at most 45 s old); the Gold Research summary is parsed once per file version and sent pre-serialised; SQLite uses WAL with a 10 s busy timeout. |
| 2 | High | **One rate limit for all users.** Behind Railway's proxy every request appeared to come from the proxy, so the 240 requests/minute limit was shared by everyone. With pages refreshing themselves, a few open tabs could block every user (HTTP 429). | Fixed: the server trusts the proxy's `X-Forwarded-For` (`FORWARDED_ALLOW_IPS`), so the limit applies per real client. |
| 3 | High | **Trade Opportunities showed a day-old scan as "current"**, with automatic scanning off. | Fixed: the scan runs by itself every 15 minutes (`OPPORTUNITY_SCAN_INTERVAL_MINUTES=15`; about 22 s per scan). The tile now reads "Data at scan time", with the latest candle's age. |
| 4 | High | **Market Scanner was stale and mostly empty:** 2-day-old manual results for 4 of the 6 instruments, mostly "NO TRADE — DATA". Its screen-reader labels said WAIT where the screen showed NO TRADE. | Fixed: the page opens with a live grid of every instrument × timeframe (6 × 14) from the Signals engine, refreshed every minute; each cell links to its checklist. The manual deep analyses stay below, labelled as such. Mislabels removed. |
| 5 | High | **Pages listed different instruments:** the Overview price cards and the Scanner showed 4 of the 6 instruments that Signals analyses. | Fixed: all six are shown everywhere by default (`FOCUS_SYMBOLS`). |
| 6 | High | **Historical Patterns read a different data set from Signals.** It read BTCUSDT from BiQuote (short history) while Signals uses Binance, and it ignored timeframes Signals builds from lower ones, so it showed "insufficient data" where Signals has analyses. | Fixed: Patterns uses the same provider and the same derived timeframes as Signals. |
| 6b | High | **Chart Analysis read BTCUSDT from BiQuote too** (232 one-hour candles), so its analyses reported "not enough data" while Signals had months of Binance history. | Fixed: Chart Analysis loads candles and runs analyses on the instrument's Signals data source. |
| 7 | Medium | **Chart Analysis decision panel:** a three-column layout squeezed into the narrow side panel, so labels overlapped ("CONFIRMATIONDATA"). | Fixed: compact single-column layout there. |
| 8 | Medium | **Paper Trading cumulative-R chart:** the bottom label (-55.03R) was cut off and the top labels overlapped. | Fixed. |
| 9 | Medium | **Paper Trading verdict read "223 / 100 closed trades".** | Fixed: "223 closed trades (the 100 needed for a verdict are reached)". |
| 10 | Medium | **The Overview downloaded full analyses** (about 300 KB every 20 s) to show five job names. | Fixed: a compact list (`GET /analysis?compact=true`), refreshed every 60 s. The Models list polls every 30 s instead of 10 s. |
| 11 | Medium | **Accessibility** (axe-core, every page): low-contrast text (grey text, green, red and amber badges); skipped heading levels; invalid ARIA on expandable Paper rows; chart containers marked as images but containing focusable parts; an unnamed table header; a scroll area unreachable by keyboard; duplicate landmark names. | Fixed: theme colours darkened to meet WCAG AA (4.5:1); card titles are level-2 headings; the remaining items corrected individually. |
| 12 | Medium | **Every browser tab had the same title.** | Fixed: "Signals · AI Trading Intel" and so on. |
| 13 | Medium | **No Content-Security-Policy**, although the API key is stored in the browser. | Fixed: a CSP allows scripts and styles only from the site itself and network calls only to the site and the configured API; a Permissions-Policy is added too. |
| 14 | Low | `/docs` and `/openapi.json` are public. They list the endpoints only; every data endpoint needs the key. | Accepted (useful for the handover). Set `docs_url=None` in `app/main.py` to hide them. |
| 15 | Low | `npm audit`: zod (client-side form validation only; the fix is the zod 4 major upgrade) and postcss inside Next.js (build time). `pip-audit`: no known vulnerabilities. | Accepted for now; upgrade zod in a later release. |
| 16 | Low | **Predictions and Chart Analysis** come from the older decision engine and run only on demand, so their results can be days old. Every result shows its time. | Accepted. Signals, Scanner, Overview and Paper Trading are the live views. |
| 17 | Low | Data Sources has 44 controls smaller than 24 px on a phone. | Open: polish. |
| 18 | Low | Vercel's automatic GitHub builds fail ("wrong root directory"); deploys work through the CLI. | Open: set Root Directory = `frontend` in the Vercel project settings. |
| 19 | Low | Railway's `railway.json` config format stops working on 2026-12-01. | Open: run `railway config migrate` before then. |

## Found by the re-test (fixed the same day)

The audit was repeated on the live site after the fixes. It found three defects introduced by the first round, all fixed and
re-verified:
- **The Overview job list failed.** The new compact list returned HTTP 500 with real data. A test now covers it with a real analysis.
- **The phone Overview scrolled sideways by 87 px.** Screen-reader-only text inside a table escaped the table's scroll box. Table
  wrappers now contain it.
- **Per-page tab titles did not apply** until they moved into Next.js route metadata.

## Not defects, but the most important facts for the owner

- **No strategy has a proven edge.** Live paper test: 223 closed trades, 21.5% winners, −0.25R per trade (95% CI −0.48 to
  +0.01). Backtest of the same rules: −0.19R per trade over 414 trades. Gold research: 1,981 setups tested, none passed. This is why
  the platform never says ENTER. It is correct behaviour, not a bug.
- **Paper trades on 3m/5m charts can stay open for days.** Their first target can be 10R or more away and there is no time stop, the
  same rule as the backtest. Changing it is a strategy change for paper trading and backtest together.
